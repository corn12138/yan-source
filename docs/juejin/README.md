## 怎么拿去发

每篇的一级标题就是候选标题，从开头一直复制到「仓库留档」之前，就是独立文章正文。末尾的「仓库留档」提供相对源码链接和历史依据，方便后续修订；这些相对链接不能直接在掘金访问，发布时删除该节，或者在仓库开放后替换为对应提交的公开链接。

建议按编号连载，标签从 `Go`、`编辑器`、`桌面应用`、`项目实战` 中选择，每篇挑两三个相关的即可。文章没有填充虚构截图；需要配图时，用自己当前运行的对应功能截图，并标注版本。源码树与流程使用纯文本代码块，复制到掘金即可阅读。

这些是依据现存材料整理的**回顾式日志**，不是逐小时的现场记录。设计文件中的日期与 Git 作者时区不完全一致，正文主要按阶段与版本叙述；[时间线与覆盖索引](SOURCES.md) 的提交日期统一换算为 `America/New_York`。没有依据的工作时长、心情故事、线上用户数和性能横评均未编造。

## 事实口径

- 历史性能和测试结果只写对应报告、对应版本；本次写稿没有重新跑产品基准、安装测试或发布流程。
- 发布记录来自仓库内的报告、release notes 与本地标签，本次未重新查询 GitHub 资产和仓库可见性。已有发布报告记载仓库为私有，因此正文不承诺读者可直接下载或查看源码，也不将项目称为已开源。
- 旧设计中的 Gio、手写词法器、6 MB 门禁属于当时方案；当前源码采用 MyGo、Chroma、10 MiB 终端体积门禁，`go.mod` 声明 Go 1.27.1。
- 旧清单仍写着「自动换行、多窗口未做」，但 alpha.4 的发布记录与源码已有实现。本系列按阶段解释这个变化，不照抄旧清单。
- 「实现了」「自动化覆盖」「原生自测」「真人实际操作」分开描述。尤其不把模拟 IME 事件写成系统中文输入法已经全面验收。

后续新增文章时，继续记录“触发问题 → 选择 → 实现 → 验证 → 遗留”，并更新 `SOURCES.md`；已发布的篇章保持当时口径，纠正事实时注明修订。
