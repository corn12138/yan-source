# Markdown 实时编辑

目标：打开 Markdown 像飞书、Google Docs 一样直接在排好的版面上改，同时文件始终是纯 Markdown，
Git 差异、外部工具、终端版都照常可用。

## 取舍

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| 富文本模型 + 导出 Markdown（飞书、Notion 的做法） | 文档以块树为真，保存时序列化 | 不采用：往返会改写用户的格式（空行、列表符号、HTML），Git 差异变脏，终端版无法编辑 |
| 源码编辑器里隐藏标记、放大标题（Obsidian Live Preview） | 代码窗格按行变字号、隐藏字节区间 | 暂不采用：砚的代码窗格是等宽格子排版（core 以格子为单位，GUI `cellAt` 命中），要重写 core 布局与命中测试 |
| 渲染视图里块级就地编辑（Typora 的块编辑） | 预览始终渲染；被编辑的那一块原位换成它的 Markdown 源码 | **采用**：复用现有解析、块→源码行映射和原生输入法编辑框，文档、撤销、保存、自动保存都是同一个 |

## 已完成（MD-17）

- 预览里双击一个块（段落、标题、列表项、引用、代码块、表格行），原位变成编辑框，内容是该块的 Markdown 源码。
- 每次修改通过 `Editor.EditMarkdownLines(col, path, version, from, to, src)` 写回：按版本校验，文档在别处变了就拒绝并退出编辑；
  写入以打字的方式合入撤销历史，保留文档原有行尾（CRLF）。
- Esc、⌘/Ctrl+Enter 或焦点离开即回到渲染。单击和拖动仍是选字，链接和“复制代码”按钮不触发编辑。
- 编辑框高度随文字换行实时变化，下面的块不跳动。

## 后续阶段

1. **编辑框的格式能力（MD-18，已完成）**：MyGo 的 `Element.TextSelection`/`SetTextSelection`（按 rune）与 `Composing` 足够，
   无需改 MyGo。格式键在 `ui/gui/markdownformat.go` 里是纯函数；Enter/Tab 经编辑框的 `HandleInput` 先于控件处理，
   用上一帧记下的选区（处理函数在两帧之间运行，读不了元素）；输入法组字时一律放行。
2. **块级结构（MD-19）**：文末与块间新增块、上下方向键在块间移动编辑、拖动块重排、表格按单元格编辑、任务框点击勾选。
3. **所见即所得的观感**：编辑中的块也套用该块的渲染字号与样式（标题大字、列表缩进），只显示光标所在行的标记。
4. **默认打开方式**：设置项决定 Markdown 默认以“实时编辑”还是源码打开；会话记住每个标签的模式。
